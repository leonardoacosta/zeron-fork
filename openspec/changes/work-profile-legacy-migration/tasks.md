# Explicit non-destructive work-profile migration execution contract

**Dependencies:** `work-profile-boundary`, `safe-resume-reconciliation`. Only exact prerequisite promotion admits implementation.
**Status:** proposed; no runtime implementation authorization.

## D. Legacy inspection and explicit migration (separate child unit)
**Depends on:** C's no-execution-on-unbound gate, A+B, and a separately approved source/target manifest format. This unit must not rewrite existing Local→Synced `LocalImporter` semantics as a shortcut.

**Owned callsites:** `crates/engine/src/profile.rs` root classification; `crates/engine/src/local_import.rs` existing importer/marker and read-root grant; `crates/engine/src/lib.rs:209-344` profile assembly, recovery, uploads and importer wiring; `crates/engine/src/rpc.rs:2473-2509` existing `LOCAL_IMPORT_STATUS` / `IMPORT_LOCAL_WORKSPACE`; tests in `crates/engine/tests/local_import.rs`, with a new `crates/engine/tests/work_profile_legacy.rs` only for public boot/migration integration.

- [ ] Introduce a read-only classification function before `DocsStore::open`, `RunJournal::open`, `recover_stale`, upload-root fallback, LocalImporter construction, preview start, relay join, or repo/account operations. Its output must distinguish explicit named root, explicit legacy identity, ambiguous legacy roots, corrupt catalog/marker, partial target and no legacy data. `None` must not map to `EngineProfile::local`, account-scoped `synced`, or development identity as a compatibility shortcut. Record the complete side-effect order in the test first; then add the smallest owning boundary in `profile.rs`/`lib.rs`.
- [ ] For `UnboundLegacy`, expose only a read-only migration-required inspection result. Prohibit regular list/watch/read session RPCs as well as writes, not only run creation. Verify the rejection occurs before stale journal recovery, `DocHost::set_sessions` command/queue drain, `LocalImporter::run`, local import marker grants, or `Uploads::from_root_with_fallback`. Existing old clients must receive a typed unsupported/migration-required error, never an empty successful workspace that implies a default binding.
- [ ] Preserve the current `LocalImporter` behavior for existing transport-account flow. Add a named-profile guard at its construction/call boundary so the existing `LOCAL_IMPORT_STATUS` / `IMPORT_LOCAL_WORKSPACE` RPCs cannot silently assign the local store to an arbitrary named profile. Keep `marker_grants_read_root` keyed to the existing org/user import only; named bindings need an explicit source-profile and target-profile grant and principal equality check before that root is readable.
- [ ] Use this concrete manifest schema in `crates/engine/src/local_import.rs` for the new named-profile migration path, without changing the existing Local→Synced marker format: `MigrationManifest { version: 1, operation_id: UUID, source: LegacySourceRef, target: WorkProfileBinding, state: MigrationState, source_digest: hex(SHA256), staged_digest: Option<hex(SHA256)> }`; `LegacySourceRef` is an enum for the existing local root and a specific account-scoped root, containing canonical relative root kind plus captured principal tuple where applicable. Persist one manifest at `{data_dir}/profiles/migrations/{operation_id}.json` using same-directory temp write, file sync, atomic rename, then parent-directory sync. This owner-local sidecar is the durable authority for progress, not the target catalog row; only publish the catalog/profile binding after `Verified`.
- [ ] Never copy the main SQLite file while excluding a live WAL. Committed rows may exist only in WAL; integrity_check does not freeze a snapshot. Acquire exclusive engine-level source quiescence without modifying source data, then open each source database read-only and use SQLite backup API into the staging database so committed WAL content is included consistently. If source cannot be quiesced or a coherent multi-file snapshot cannot be proved, remain held. No source checkpoint, overwrite or journal replay. Use existing rusqlite backup feature only after checking workspace dependency support; exact feature/source patch must be authored before implementation.
- [ ] Manifest binds a frozen source inventory, the produced consistent SQLite snapshots, journals and allowed uploads. Do not compare source main-DB byte hash to backup bytes as logical equivalence proof. For SQLite compare deterministic selected logical table/schema contents from the same snapshot or a documented snapshot identity; for ordinary files hash length-delimited canonical path and content bytes. Reject symlinks/special files and source mutation while copying. Validate staged DB integrity and row-level invariant counts, including assignment current/history/replay and pending command state. A source-generation fence must still match before publication. Exact snapshot/digest implementation and tests are required, not supplied by prose.
- [ ] Use these states and transitions: `Prepared` is durably written before creating stage; `Copying` before first copy; `Verified` only after both source revalidation and staged digest match; `Published` only after catalog binding commits. Failures leave `Prepared`/`Copying`/`Verified` as durable uncertainty, never mark ready; a separate error field may record diagnostic text but cannot change the authorization state. On retry with the same operation ID and exact source+target, verify/reuse stage; a different tuple is `OperationIdConflict`. If catalog commit outcome is uncertain, reopen catalog and manifest, then reconcile by exact target binding and digest before answering. No cleanup of source or uncertain stage in this slice.
- [ ] Only after manifest freeze above implement copy-to-new-empty-target. Never move/delete source, overwrite any target, or copy credentials. Build at `{target_root}.staging-{operation_id}` on the same filesystem so final rename is atomic; reject pre-existing final target, symlinked roots/components, or a stage belonging to another operation. After `Verified`, atomically rename stage to target, then commit target catalog binding and persist `Published`; boot still refuses execution between rename and catalog commit unless exact manifest reconciliation proves this same operation. On crash/failure keep target non-executable and retry only the same source+target+operation. Return typed uncertain/held result for source mutation, partial target, corrupt manifest, or lost acknowledgement.
- [ ] Add public-interface tests in `crates/engine/tests/work_profile_legacy.rs`: (1) absent opt-in preserves existing Local/Development/Synced behavior and current Local→Synced importer regression; (2) explicit UnboundLegacy inspection leaves legacy bytes/metadata unchanged and blocks all data RPCs; (3) restart while held does not call stale recovery or dispatch; (4) source mutation after preflight prevents publish; (5) existing/partial target refuses without overwrite; (6) trigger/injected file-copy failure then reopen stays held and source digest unchanged; (7) successful copy publishes only after verification, then restart selects same target binding; (8) credential files are neither copied nor readable; (9) existing account `marker_grants_read_root` does not authorize unrelated named profile; (10) crash after rename before catalog commit reconciles only the exact same operation and never opens a different target.
- [ ] Only after D tests pass may the implementation make named-profile migration available. Keep legacy inspection and migration separate RPC operations with typed outcomes; a transport login or profile selection is not migration consent.

## C-D split recommendation and current blockers
- [ ] Coordinate DAG metadata changes with the parent owner; this worker changes only C-D prose in design.md/tasks.md. Required dependency semantics: A+B contract child precedes resource-enforcement and runtime-binding children; runtime binding depends on both; D migration depends on runtime binding. Avoid any edge from runtime binding to a resource-enforcement unit that depends on the entire unsplit parent, which is cyclic.
- [ ] Distinguish compatibility rollout states: absent `work_profile_selection` on an installation that has not opted into named profiles continues the existing Local/Development/Synced behavior unchanged, including existing Local→Synced import. Explicit `Named(binding)` may never fall through to that default. `UnboundLegacy` is an explicit opt-in to read-only migration inspection, not the new spelling for every pre-existing installation. If named profiles are enabled and a legacy root cannot be uniquely bound, hold it in inspection-only migration-required state. Keep these paths disjoint in code and tests.
- [ ] Source/target selection requires explicit authorized input. Exact snapshot/digest/publication implementation remains a technical planning task; do not label it a user blocker or delegate it as guessing.


## Required scenarios
- C01: No explicit source/target binding: legacy source stays unchanged and execution held.
- C02: Crash during staged copy: destination is not published ready and source remains intact.
- C03: Source changes or target already exists: reject without overwrite or merging profiles.
- C04: Verified copied data is published atomically, but copied run journals do not auto-resume.

## CI phase after every implementation iteration
Run exact feature tests plus required round CI from `../prd-execution-map/design.md`, bind evidence to integrated revision, no missing/failed/stale promotion.

## Rollback
Keep source immutable; retain staging and incomplete marker for diagnosis. Never delete original or overwrite target. Revert capability without erasing migration receipts.
